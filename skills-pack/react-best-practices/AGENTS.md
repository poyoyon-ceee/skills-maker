# AGENTS

## 作業原則

- 作業開始前に、プロジェクト構成、現在のブランチ、Gitの変更状態を確認する。
- ユーザーが指定したファイル、関数、スコープだけを変更する。
- 既存の設計、命名規則、コードスタイルに従う。
- 不明点が結果に大きく影響する場合は、作業前に確認する。
- 軽微な不明点は、既存コードから合理的に判断し、その前提を報告する。

## 変更時の注意

- 依頼されていないリファクタリング、変数名変更、整形、最適化を行わない。
- 既存コメント、ログ、デバッグ出力を削除しない。
- 自動フォーマット、改行コード変更、文字コード変更、import整理による不要な差分を発生させない。
- 新しい依存関係を追加する場合は、必要性と影響を説明する。
- ファイル削除、大規模変更、設計変更は実行前に確認する。

## Git運用

- mainブランチを直接変更しない。
- 開発作業は原則としてdevブランチで行う。
- コミット、プッシュ、マージ、リベースは、ユーザーの明示的な指示がある場合のみ行う。
- コンフリクトが発生した場合は、勝手に解消せず内容を報告する。
- pull前に未コミットの変更がないか確認する。

## 検証と報告

- 修正後は、可能な範囲で構文確認、テスト、ビルドを実行する。
- テスト失敗を隠したり、テストを通すだけの場当たり的な修正を行わない。
- 実行した確認内容と結果を簡潔に報告する。
- 実行できなかったテストや未確認事項を明記する。
- 変更したファイルと変更内容を最後に要約する。
