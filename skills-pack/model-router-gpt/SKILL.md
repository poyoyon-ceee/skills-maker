# model-router-gpt

CodexのGPTモデル（Luna/Terra/Sol）向けの大量探索Skill。通常ツールで候補を絞り、必要な読解量が大きければLunaに一次抽出、整理が必要ならTerraに統合を委任する。Solが重要原文を確認して判断する。Android、Python、Web、MT4/MT5、Obsidian、文書・ログなどで共通利用する。

## 適用範囲と実行能力

- CodexのGPTモデル向けに使う。他のAI環境のモデル名・委任方法には適用しない。
- プロジェクトの `AGENTS.md` にある重要ファイル、禁止事項、テスト、書き込み範囲を確認する。このSkillはそれらの許可を拡張しない。
- 現在公開されているsubagentツールのschemaを使う。**Luna/Terraはモデルを明示する。** 指定を省いて親のSolを継承させない。
- 探索の点検・検索漏れ確認もこの分担に含める。機械的な点検は通常ツールで行い、子による意味判定が必要ならLunaを明示する。Luna/Terraを省いた後にモデル無指定のSol子へ探索・点検を渡すことはしない。
- 委任する際は [references/delegation.md](references/delegation.md) の利用可能な方式だけを読む。現在のDesktopでは `collaboration.spawn_agent` の `model` と `fork_turns: "none"` を使える。
- 親モデルはユーザーの選択に従う。通常のSol親は司令塔・最終回答を担当するが、このSkillが親モデルを切り替えるわけではない。親がSol以外なら、実際の親モデルをReportに記す。
- Skillの自動選択はタスクとdescriptionの一致に依存する。`$model-router-gpt` でも明示起動できる。これは強制hookではない。

## 分担

| 担当 | 処理 |
| --- | --- |
| rg / PowerShell / shell / Git / Python・parser | ファイル列挙、キーワード検索、差分、件数、機械的抽出・変換。AIより先に行う。 |
| `gpt-5.6-luna` | 多数候補の関連度判定、ファイル・関数・根拠行の一次抽出、ログ・メタデータ・粗い要約、単純分類・定型作業。重要な最終判断はしない。 |
| `gpt-5.6-terra` | 整理が必要なLuna結果の比較、重複・時系列・矛盾の整理、構造化・統合。 |
| Sol / 実際の親 | タスク分解、設計、難しいデバッグ、セキュリティ、重要原文の確認、最終統合・レビュー・回答。 |

単なる機械検索だけで答えが出るなら通常ツールで終了する。短い仕事にLuna→Terra→Solの全段階を強制しない。多数の候補に意味の判定が必要ならLuna、整理が答えを改善する場合だけTerraを使う。

## 実行手順

1. **親が問いを分解する。** 対象ルート、探すテーマ、最終判断に必要な根拠、読み取り/変更の許可を定める。
2. **原文を広く読む前に通常ツールを使う。** `rg --files`、`rg -l`、絞った `rg -n`、Git差分、parser等で候補と該当箇所を抽出する。プロジェクトで指定された重要ファイルは検索語に依存せず候補へ加える。秘密・依存物・生成物・バイナリは必要性と許可に従って除外する。 親への出力は件数・短い候補一覧・必要な一致行に限定する。少数の短い原文で足りる場合は親が限定して確認し、広い読解が必要な候補は次の手順でLuna委任を判断する。hash照合や集計はツール内で完結し、全hash・全メタデータの一覧を親へ出さず、件数・差分・失敗だけを返す。
3. **検索後に委任の要否を判断する。** 件数だけでなく、回答に必要な関連原文の行数/サイズと意味の抽出・分類の量を通常ツールで見積もる。検索結果と少数の短い原文で答えられるなら親の限定読みに進み、Luna/Terraを起動しない。13件の短文も自動委任せず、少数の巨大ログも件数だけで除外しない。原文を広く読み意味の判定を続ける必要がある場合にLunaへ限定した一覧/検索式/行範囲を渡す。起動・共通指示・返却・親の再確認にも負担があるため、節約を件数や行数だけで保証しない。大きければ独立したテーマでバッチ化し、利用可能な枠内で並列にする。
4. **Lunaには根拠を持ち帰らせる。** 親の全履歴やリポジトリ全文を渡さず、目的・範囲・具体的出力形式を明示する。親へ大量原文を返すことも避ける。
5. **必要ならTerraへ整理を委任する。** Lunaの小さな結果と必要な元ファイルの位置だけを渡す。結果が既に短く一貫しているならTerraを省く。重複・矛盾・採用状態の混在があり、その比較整理が回答の正確さを改善する場合だけTerraを使う。バッチが複数という理由だけでは起動しない。矛盾、重複、旧方針/現行/提案、未解決を区別させる。変更を伴う整理ではユーザーの許可範囲・所有ファイル・テストを明示し、同一ファイルへの並行編集を避ける。
6. **親が重要原文を直接確認する。** 採用済み決定、設定値、数値/日付、例外、失敗理由、セキュリティ、矛盾の解消は要約だけで確定しない。根拠ファイルの必要な行範囲を直接読む。原文が確認できない判断は未確認と明示する。
7. **回答とRouting Reportを返す。** 完了した処理だけを実測値で示す。不要な段階は `skipped`、モデル指定不可・証拠不足はその制約を記す。

親によるフォルダ全体の `Get-Content`、全ファイルの連結、無限定の全文出力は避ける。検索候補の見落としが判明したときは検索語・構造検索・対象範囲を調整し、必要なバッチだけ追加する。

## 子への入力と返却

委任には次を含める。サイズは仕事に合わせて小さく保つ。

```text
目的: [具体的な問い]
対象: [絶対ルート、候補一覧/検索式、必要な行範囲]
境界: [プロジェクトルール、読み取り専用または許可済み変更範囲]
返却: path:line、関数/見出し、関連理由、短い根拠、状態
保持: 決定、失敗理由、数値、日付、設定値、固有名詞、例外、矛盾、TODO、未解決
区別: 現行の採用事項 / 旧方針 / 提案 / 失敗 / 未確認
計測: 列挙件数、内容検索件数、直接確認したuniqueファイル数、未確認範囲
禁止: 範囲外探索、重要な最終判断、親履歴の要求、大量原文の返却
```

「候補24件」だけで「24件を確認済み」としない。途中終了、未読、検索失敗も返させる。件数や引用位置が判断に必要な場合は親が検索出力と照合する。

## Routing Report

subagentを使った、または大量探索を扱ったタスクでは、最終回答の末尾に小さなReportを付ける。下は項目例であり数値の初期値ではない。

```yaml
Routing Report:
  Local tools:
    tools: [rg, PowerShell]
    files_enumerated: <実測またはunknown>
    files_content_searched: <実測またはunknown>
    candidates: <実測>
  Luna:
    requested_model: gpt-5.6-luna
    agent: <標準ツールが返した識別子>
    configured_model: <標準UI/APIで確認した値、確認できなければunknown>
    files_inspected: <実測>
  Terra:
    requested_model: gpt-5.6-terra
    agent: <識別子、使わなければskipped>
    configured_model: <確認値またはunknown>
    results_consolidated: <実測>
  Parent:
    model: <実際の親モデルまたはunknown>
    original_files_verified: <判断根拠のuniqueファイル数>
    work: final reasoning, review, and answer
```

- ファイル列挙、内容検索、子の直接確認、親の原文確認を混同しない。利用量/時間も実測・比較できたときだけ示す。
- モデルの自己申告は証明にならない。指定モデル、標準UI/APIで確認した設定モデル、実行telemetryを区別する。`thread/read` の `model` は設定/最新保存モデルでありbackendの各turn実行証明ではない。
- 既存のsubagent表示・ツール履歴を証拠として使い、確認できない値は `unknown` にする。Reportのために独自の常駐ログ、hooks、global configを作らない。
- モデル指定またはsubagent機能が使えない環境では、明記して通常ツールと親の限定読みに縮退する。別モデルをLuna/Terraと偽って記さない。Skillだけでの遵守やコスト減少を保証しない。
